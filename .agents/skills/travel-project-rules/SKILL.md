# 旅游规划工作台：项目规则

先确认仓库、工作区和未提交改动，阅读根目录 `README.md`、`MEMORY.md`、`DECISIONS.md`、`TODO.md`。这些文档是不同时间的快照，实际行为以当前代码和验证结果为准；发现冲突时说明，不要把过期状态当成事实。

- 未知价格、查询失败和未配置不能当作零；估算、示例、查询快照与可订报价应清楚区分。
- 算最便宜只产生候选，用户选择并确认后才写入行程；选择不等于购票。
- 重新开始时先保存，保存成功后再清空；不要将它扩展成其他保存策略，除非用户要求。
- 地图涉及高德与其他地图时核对坐标系及转换；查看地铁线路不应自动加入行程。
- 测试优先使用隔离的浏览器上下文和模拟数据，避免改动用户真实行程；实时接口测试要说明依赖与实际结果。
- 保留已有工作区改动；更新项目记忆、提交、推送及部署按当前用户授权和适用规则执行。

按改动范围选择构建、单元测试和交互验证；结果分别说明验证范围、未验证项和已知风险。
