# 高德路线独立互动预览实施计划

> **范围已更新：**本计划仅覆盖驾车小样，已由 [高德网页版全界面复刻与工作台接入计划](2026-11-16-amap-web-full-replica-integration.md) 取代。此文件保留为驾车子任务参考；不应据此缩小用户要求的全站范围。

> **执行提示：**使用 `superpowers:executing-plans` 或等效的逐项检查流程执行。此文件是计划，不代表已经实施；任何提交、推送、部署和项目记忆写回都不包含在本计划授权内。

**目标：**先做一个与旅游工作台隔离的桌面网页，参考用户提供的高德网页版驾车截图，使用真实高德地图和真实驾车查询，验证“输入并选择起终点 → 查询 → 选择方案 → 地图与卡片同步 → 展开指引”。

**架构：**新建独立静态目录，由现有 18647 本地服务提供页面；复用已有的高德 JS API 配置、安全代理、地点和路线接口。预览只在内存保存状态，不挂载工作台 store，也不调用备份、配置修改或车票接口。地图路线使用高德返回的真实 GCJ-02 坐标，逐方案绘制；截图工具只用于视觉对照，不作为底图。

**技术栈：**原生 HTML / CSS / JavaScript、现有 Node 本地服务、高德 JS API 2.0、现有 `/api/places/search` 与 `/api/routes/search`、Playwright 隔离浏览器。可参考现有 Vue 地图实现，但不要求迁移成 Vue。

## 任务 4：地点搜索与选择

1. [ ] 输入框初值可显示参考图中的两个地点名称，但只有用户从接口候选中选择后，才将该输入对应的坐标视为有效；可提供“查找这两个地点”作为明确动作，不得对输入字符串臆造坐标。
2. [ ] 输入后使用当前输入发送地点查询，列表显示名称、城市、地址；候选缺少有效 `gcj02` 时标记不可选。使用 DOM `textContent` 写入外部返回文字，避免注入。
3. [ ] 同一输入快速变化时使用递增请求序号：旧请求即使后返回，也不能覆盖最新输入的候选。输入被修改后清除该端点原有选中坐标及旧路线；两端选中前查询按钮不可用。
4. [ ] “交换”同时交换输入文字与已选地点对象，并清除旧路线；如果某端输入已修改但未选候选，只交换文字与空选中状态。
5. [ ] 地点查询失败、超时、无结果、名称重复或用户未选候选时，分别给出可理解的提示，不自动回放之前搜索词的结果。

## 任务 5：驾车路线与地图联动

1. [ ] 两端均有有效 GCJ-02 坐标后，调用 `POST /api/routes/search`，使用上面约定的 `driving` 输入。请求开始时清除上一次路线状态；请求序号、端点或查询策略变化时丢弃过期结果。
2. [ ] 每个实际返回的 `routes[i]` 生成一张方案卡，卡片显示序号、时长、距离；真实返回红绿灯数和道路名时显示，缺失时显示“暂无”或隐藏并保持口径一致。费用仅在实际返回且含义明确时显示。
3. [ ] 解析 `polylines` 中 `lng,lat;lng,lat` 为 `[lng, lat]`；跳过无效坐标，不跨断点补直线。用 `AMap.Polyline` 分方案绘制；参考高德提供的颜色、描边和箭头方式，选中线较粗且位于上层，未选线较浅。路况分段只有接口实际提供且可映射时才着色；无数据时用中性色并注明。
4. [ ] 使用单一 `selectedRouteIndex` 驱动卡片和地图：点击卡片调用 `selectRoute(index)` 更新所有卡片及线；点击有几何信息的线也调用同一函数。`aria-pressed`、详情、时长和显示的路线索引保持一致。
5. [ ] 始终以所选起终点的真实坐标画起点、终点标记。`map.setFitView` 留出左侧面板占位；选择方案时不得把路线隐藏在面板下。只返回一条方案时只显示一条；返回多条时按实际数量展示，不伪造方案 2 或 3。
6. [ ] “展开详情”仅展示选中方案真实返回的 `instructions`；缺失显示“暂无路线指引”。点击另一个方案后详情与当前方案同步，不保留上一条的内容。
7. [ ] 查询失败、0 方案、缺失或部分几何、重叠路线无法通过鼠标区分、超时和组件销毁均要明确处理：无几何时保留可读卡片并提示；允许用户通过卡片切换；清除覆盖物并忽略迟到回调。不得让上次结果冒充本次结果。
