# 高德地图与旅游工作台互动实施计划

> 执行说明：按 `superpowers:executing-plans` 分阶段执行。第一阶段先做独立预览；用户确认预览前，不替换正式工作台现有地图和界面。本文是计划，不表示下述功能已经实现。

**目标：** 以用户提供的高德网页版画面和实际操作为对照，在旅游工作台中实现地图左键、右键、地点收藏、驾车/公交/步行/骑行路线及每日时间安排之间的联动。

**方案：** 继续使用高德 JS API 2.0 负责地图、标记和地图事件；使用官方路线组件与 Web 服务分别验证路线数据及显示能力。工作台负责自己的地点、收藏、行程、时间和跨栏选中状态。先在独立页面比较官方默认面板与自定义面板，再决定正式页面的组合。

**技术：** Vue 3、Pinia、Vite、现有 Node 本地服务、高德 JS API 2.0、高德 Web 服务 v5、独立 Playwright 浏览器。

## 3. 使用体验与功能约定

### 3.1 左键：选地点与双向联动

- [ ] 点击底图可识别的地点、搜索结果或工作台已有标记时，选中同一地点，展示名称、地址及接口实际返回的图片、评分、营业时间等；无数据明确显示“暂无”。
- [ ] 地点详情提供“收藏/取消收藏”“加入想去”“加入第 N 天”“设为起点”“设为终点”“去这里”；选定住宿有有效坐标时提供“从住宿出发”。“去这里”填入终点并引导选择起点，双方坐标就绪后由用户触发查询。
- [ ] 点击左侧真实地点卡片，地图定位并高亮对应标记；点击地图标记，左侧对应卡片同步选中。地图详情和行程面板共用稳定地点 ID，不用名称匹配同名地点。
- [ ] 以高德 POI ID 查询详情；普通地点位置保留 `location`。路线终点优先使用可用的入口坐标，起点按实际入口/出口场景处理，缺失时回退到地点坐标；坐标不合法时不查询。
- [ ] 没有 POI ID 的地图任意坐标保留为用户选定的坐标位置，生成工作台内部 ID；逆地理编码给出的附近地址不能冒充成真实 POI 或其入口。
- [ ] 工作台显示、收藏与路线查询失败时保留已选数据；不把名称相同、地址不同的地点自动合并。

高德公开的[地点搜索与详情文档](https://lbs.amap.com/api/webservice/guide/api/newpoisearch)列有名称、地址、营业时间、评分、图片和入口等字段，是否返回取决于请求和地点。完整长篇介绍、评论正文与高德账号收藏同步未在已核对的接口中确认，不用假数据填充；需要时提供打开高德地点详情的入口。

### 3.2 右键：复现已观察到的地图菜单

- [ ] 地图右击后，按实际截图显示“设为起点、设为途经点、设为终点、这是哪儿、搜周边、设为地图中心点、清除路线”，并固定本次右击坐标，点击菜单不会误用下一次鼠标位置。
- [ ] 起点/终点/途经点变更只影响当前路线草稿；途经点的可用性按交通方式和接口实际能力验证。驾车拖拽通过 `AMap.DragRoute` 独立试验，其他方式不假定支持同样的拖拽能力。
- [ ] “这是哪儿”使用逆地理编码；“搜周边”使用周边地点搜索；“地图中心点”移动视野；“清除路线”清除当前地图路线和草稿结果，不删除已收藏地点或已安排的行程。
- [ ] 地图边缘打开菜单时调整位置以避免溢出；点击菜单外部、按 Escape、切换地图模式时关闭；测距等工具启用时不误触地点选择。

官方依据：[自定义右键菜单](https://lbs.amap.com/demo/javascript-api-v2/example/contextmenu/custom-contextmenu)、[逆地理编码](https://lbs.amap.com/api/javascript-api-v2/guide/services/geocoder)。

### 3.3 收藏、住宿与行程

- [ ] 收藏/取消收藏只改变当前工作台的收藏状态；详情、左侧列表、地图星标同步，重复收藏不产生重复条目。取消收藏不删除已安排地点。
- [ ] “加入想去”与“加入某一天”分开：前者进入待安排列表，后者将地点写入指定日期。拖动/移动已有地点时不得无提示覆盖备注或其他日期的数据。
- [ ] 住宿可选择真实地点作为位置；酒店没有有效坐标时明确引导选点。位置选择不代表已订房，也不把人均消费冒充房价。
- [ ] 路线查询默认是草稿；选择“收藏路线”或“加入第 N 天”后才写入用户指定的工作台数据。路线收藏不冒充高德账号收藏。
- [ ] 地图收藏、地点列表与每日安排显示同一份状态；恢复旧旅行时兼容旧版 `plans`、`customPlaces`、`savedPlaces`、`dailyRoutes`。当前旅行本地状态与“重新开始时保存旅行快照”保持现有不同语义，不擅自改为云同步。

### 3.4 路线结果与地图互动

- [ ] 路线面板可选起点、终点、交换位置、清除、驾车、公交、步行、骑行；同名搜索结果显示地址供用户选择。
- [ ] 驾车按接口实际返回显示多方案：列表与地图对应，选中方案加粗高亮，未选方案变淡；点击方案卡或地图线路均切换同一选中状态，并展示可用的时间、距离、费用、红绿灯数及途经道路。
- [ ] 可用时依据接口返回的分段路况绘制颜色；缺少分段路况时显示统一线路并说明，不能凭空生成拥堵状态。策略包括推荐、躲避拥堵、避免收费；实际参数按所用接口版本映射，不能混用 JS API 和 Web API 的策略值。
- [ ] 公交按实际返回展示线路组合、上/下车站、换乘、总时间、步行距离、票价与各步路线；推荐、步行少、换乘少、不乘地铁以及日期/出发时间以接口支持和实测为准。
- [ ] 步行和骑行展示道路摘要、时间、距离、可展开的逐步指引及方向提示；有多少方案就展示多少，不补造路线。
- [ ] 起终点/日期/方式/策略/途经点变化后，旧查询不可覆盖新结果。查询中、无结果、权限错误、缺少几何分别显示清楚；不画直线冒充道路路线。
- [ ] 通过起终点和选中的地点 ID 构造[高德路线调起链接](https://lbs.amap.com/api/uri-api/guide/travel/route)供用户查看；只承诺该接口文档支持的参数，不承诺高德账户或精确备选方案同步。

### 3.5 每日时间分配

- [ ] 每天保存一个可编辑的起始出发时间；每次地点访问保存该次到达、停留时长、离开时间，交通段保存方式、实际查询返回的预计时长和查询时间。停留时间属于“某天的某次访问”，不能写在共享 POI 上覆盖其他安排。
- [ ] 对有完整输入的连续段计算：`到达时间 = 上一段出发时间 + 交通时长`；`离开时间 = 到达时间 + 本次停留时间`。餐饮、休息、等待可作为用户添加的安排；未知时间显示待填写，不按 0 处理。
- [ ] 固定预约、车次或用户锁定时间不自动覆盖；新计算与固定安排冲突、超过已知营业时间或跨天时显示冲突或日期变化，由用户调整。
- [ ] 调整顺序、日期、地点、住宿、出行方式或途经点后，仅受影响的路线及衍生时间标记过期；旧查询返回时不能覆盖新顺序。重算时展示来源和查询时间；未完成查询的路段不加入已知总时长。
- [ ] 公交日期/时间能否影响查询及未来驾车耗时的可用范围须分别验证。实时查询得到的估计不声称是未来实际耗时。

时间计算示例仅用于验收，不是真实高德数据：09:00 出发，交通 20 分钟，到达 09:20；停留 90 分钟，离开 10:50；再出发交通 25 分钟，下一站 11:15 到达。

## 6. 验收清单

### 6.1 必须通过的互动

1. 搜索或左键点击地点 → 显示正确详情 → 收藏 → 左侧和地图同步 → 取消收藏后已安排地点仍在。
2. 右击任意位置 → 选择起点、终点或途经点 → 坐标对应右击位置；“这是哪儿”、搜周边、中心点和清除按约定工作。
3. 选择住宿地点 → 从住宿到景点查询；无坐标、同名地点、查询失败均提示并保留数据。
4. 驾车、公交、步行、骑行分别显示接口实际方案；点击地图线路与点击结果卡同步，策略和出发时间按已验证能力工作。
5. 选中路线后明确加入某一天 → 设定出发与停留时间 → 显示交通/到达/离开时间；换序、跨日或固定预约冲突时正确更新或提示。
6. 快速切换地点、日期和方式时旧响应不会覆盖当前状态；查询失败、无路线、字段缺失时没有虚构路线或费用。
7. 刷新或从既有快照恢复后，地点、收藏及已确认行程符合现有保存规则；单次查看路线不自动写入每日安排。
8. 不同窗口宽度与地图分栏调整后可操作；地图隐藏/重新打开不会丢失已确认状态或产生重复覆盖物。
