# 高德网页版全界面复刻与工作台接入实施计划

> 本文是实施计划，不表示功能已经完成。执行时按阶段记录结果；用户视觉验收前，不能以测试通过代替用户认可。

**目标：**以用户提供的高德网页版截图和可观察的高德网页为参考，尽可能 1:1 复刻整个网页版的界面与可观察互动；先交付可独立使用的真实地图预览，完成核验后再接入旅游工作台，并保留工作台原有旅行数据和功能。

**范围：**高德网页的首页、地图、搜索、地点、路线、工具及实际观察到的其他功能都纳入调查和复刻清单。驾车、公交、步行路线是其中一部分，不是全部范围。最终是否达到 1:1，以逐状态对照、真实功能验证及用户视觉验收为准；无法观察或无法实现的项目要逐项列出，不能当成已完成。

**架构方向：**独立预览与工作台解耦，但从开始就定义清晰的地图组件、服务接口和事件契约，方便随后集成。地图使用真实高德底图及可用服务，界面由本项目实现；不将静态截图、模拟地图或演示数据冒充真实功能。工作台候选接入点为 `旅迹风格预览/src/components/TravelMap.vue`、`Workspace.vue`、`src/stores/trip.js` 和 `src/ui/mapFocus.js`，实际改动须先核实当前代码。

**参考来源与证据范围：**用户提供的三张截图直接展示旧版公交、驾车和步行的界面；[高德当前网页](https://ditu.gaode.com/)及[旧版地图页面](https://maps.gaode.com/plan)可用于发现入口，但仅凭页面文字不能认定各按钮互动已验证。[高德 JS API 插件说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/plugins)和[路线规划说明](https://lbs.amap.com/api/javascript-api-v2/guide/services/navigation)可用于核实开放能力；这些文档不代表高德网页版的原始 UI 和业务代码已经公开，也不保证接口行为与网页完全一致。执行时应实地复核。

## 执行前约定

- [ ] 明确参考版本：用户三张截图是旧版高德网页版的公交、驾车、步行界面；其他界面先实地观察并记录版本、网址、时间、分辨率、缩放和交互状态。网页新版如与截图不同，分开记录，不把两个版本说成同一版；缺少旧版参考的状态列为待确认。
- [ ] 以截图中可见的旧版作为已提供的视觉锚点；其他功能先观察。建立「功能—页面状态—截图/录屏—操作—数据来源—实现结果—差异」清单，不因为某功能尚未观察就自动排除。
- [ ] 只读观察高德网站；不操作用户账号、收藏或其他线上个人数据，不将密钥、账号或个人行程发送给第三方复刻工具。网络请求可能消耗地图接口额度，实测前检查现有配置和额度，控制请求量；付费或额外购买需单独授权。
- [ ] 先独立预览，再由用户查看效果，确认后进入工作台接入。若 SDK 或开放接口缺少能力、账号权限、参考页面或数据，记录具体差异及备选方式，不以假按钮、伪结果或跳转外站冒充 1:1 完成。
- [ ] 不改真实旅行、备份及项目记忆文件；不自动提交、推送或部署。执行期间若用户单独授权 Git 提交，先审阅差异并只暂存本任务确认的文件。

## 阶段 1：确认基线和保护现有工作

- [ ] 执行 `git status --short`、`git branch -avv`、`git worktree list` 和最近提交检查，记录执行时的真实状态；对照项目说明和实际入口。当前检查时根目录在 `main`，提交为 `79a553c`，且地图文件、独立预览及工具目录存在未提交更改；这一快照可能变化，执行时必须重新核实。
- [ ] 逐项查看相关未提交文件与提交版本的差异，辨认哪些是应保留或参考的工作。不得重置、清理、覆盖、自动暂存或擅自 stash；不把用户原有修改混进自己的提交。
- [ ] 用户要求使用 Git 管理时，从核实后的合适提交创建独立 `codex/` 分支或工作树，先确认分支名与目标路径没有冲突。**Git 新分支或工作树只继承已提交内容，不会自动携带未提交修改。**必要的现有预览、截图或代码，先逐文件审阅，再以可追溯的方式复制或移植并核对，不覆盖原文件。若基线不能安全分离，先明确具体冲突，不强行操作。
- [ ] 工作树及分支的建立、提交和合入均在执行阶段按当时授权处理；当前规划阶段不创建分支、不提交、不合并。未跟踪的截图及参考材料按需复制并校验，不能假设它们已由 Git 保存。

## 阶段 2：采集全站参考和建立验收矩阵

- [ ] 逐一查看首页和地图初始状态；搜索输入、建议、结果、空结果、详情与返回；地图点选、右键及弹层；工具栏和图层；地点收藏或相关入口；路线规划各方式、策略、结果、详情及切换。记录观察到的所有其他入口和次级页面，包括账户、分享、扫码、外链、帮助等，状态标为「已观察」「需要权限」「暂不可观察」。
- [ ] 至少保存用户三种路线截图对应的实际尺寸、布局、颜色、字体、间距、边界、图标、按钮状态，以及地图线条的颜色、宽度、箭头、层级、起终点和公交换乘标记；区分地图本身与页面覆盖层。
- [ ] 建立逐状态清单：入口、前置条件、点击或输入、反馈、关闭和返回、异常、是否联网、对应截图与验收方法。搜索异步响应、地图拖动缩放、路线切换、遮挡及窗口变化都要有对应场景。
- [ ] 以用户截图的旧版作为已知基准；对于新版特有功能、旧版无法访问的内容明确标注来源和待确认项。先形成可审阅的清单，再开始逐项实现，发现新入口随时补充。

## 阶段 3：建立独立预览和数据隔离

- [ ] 先核查本地服务、JS API 配置、安全代理、接口调用方式及目录约束，确定独立预览路径；建议位于 `旅迹风格预览/高德全页独立预览/`，不得覆盖已有 `路线界面独立预览/`。预览必须能展示真实可拖动、可缩放的高德地图。
- [ ] 设计独立的地图外壳、面板、地图图层、搜索、路线、工具和状态模块，明确将来嵌入 Vue 工作台所需的输入、输出与销毁流程；避免把整个页面写成无法拆分的单个脚本。
- [ ] 预览状态默认仅保存在内存，不挂载工作台 store，不读取或写入真实旅行、备份、收藏及配置。若同源复用现有本地服务，浏览器存储和 Cookie 是共享的：预览代码不得使用工作台存储，自动化使用全新隔离浏览器上下文，并通过网络拦截只放行地图显示与查询所需接口，禁止工作台数据接口。若选择独立端口，先验证主机、来源、安全代理和密钥域名限制，不能假设跨端口天然可用。
- [ ] 查询复用已经存在且经过核查的地图配置、安全代理、地点和路线能力；核对 JS SDK 与后端接口的数据格式并统一转换。密钥通过已有配置处理，不能写入前端源码、日志、截图或计划文档。
- [ ] 页面刷新、断网、密钥未配置、查询失败、接口限额时给出真实状态。独立预览只能访问被允许的接口，不能通过集成过程触碰用户数据。

## 阶段 4：复刻地图首页、搜索和地点

- [ ] 按参考实现地图填充、左侧面板、顶部工具、缩放与定位控件、浮层及层级；地图本身支持真实拖动缩放，遮挡、窄窗口和展开浮层时按参考调整布局。
- [ ] 实现城市选择、输入建议、搜索结果列表、加载/空结果/失败和详情面板；选择结果时地图定位与标记同步。连续输入、清空和返回时，旧请求不能覆盖新结果。
- [ ] 实现地图点选、右键菜单、定位、地图样式、卫星图、路况、测距等实际观察到的工具；各工具按参考表现互斥或共存。需要权限或数据而无法实现时保留差异记录，不伪造。
- [ ] 地点详情、图片、营业信息等只显示真实返回的数据，字段缺失时清楚显示；不把搜索关键词当作已核实地点，不拼造评论或景点介绍。

## 阶段 5：复刻全部观察到的路线规划

- [ ] 依据参考实现路线面板的交通方式、起终点输入建议、交换、清空、出发、错误状态及面板开合。每种方式均检查可观察到的策略与结果布局，观察到骑行或其他方式时一并纳入。
- [ ] 驾车：支持真实多方案查询、策略切换、选中方案、地图高亮与结果卡同步、路线指引；真实接口返回路况或红绿灯等数据时按参考展示，没有数据时不编造。
- [ ] 公交：支持真实线路方案、换乘、步行段、站点与选中方案联动；城市、跨城、出发时间等按照实际接口能力验证，无法支持的参数和影响单独列出。
- [ ] 步行及观察到的其他方式：展示真实路线、方向箭头、起终点、距离、时长与步骤；切换方式、起终点或策略时清除过期图层和结果，防止旧请求覆盖。
- [ ] 地图上多方案、路线标注、层级、线宽、方向、公交步行段及节点按对应参考逐项对照；地图位置和底图必须保持真实，截图仅作对比素材。

## 阶段 6：补齐其余全站功能与可用性

- [ ] 按阶段 2 的完整清单，逐项实现仍未覆盖的入口及互动，包括观察到的收藏、分享、账户、地铁、帮助和其他工具；逐项写明是真实可用、仅本地体验、需要账号/权限、外部跳转或暂不支持。
- [ ] 账户同步、跨设备发送、付费或受限功能不能使用假数据伪装；确无可用方式时列为未达 1:1，说明需要什么条件及备选方案，由用户决定后续处理。
- [ ] 核对键盘输入、焦点、面板关闭、滚动、加载、重复点击、网络失败、浏览器窗口缩放和低分辨率下的表现；按参考核查遮挡与交互反馈。

## 阶段 7：独立预览验收

- [ ] 用同一参考版本、同一窗口尺寸、缩放、地图地点与交互状态，分别截图对照首页、搜索、详情、地图工具及各路线状态；保留参考图、复刻图及差异说明。实时底图、路况、文字渲染可能变化，像素差异只作定位线索，仍需逐项人工检查。
- [ ] 自动化检查核心链路：搜索到选点、地点详情、各路线查询与切换、地图覆盖物更新、错误和重试；真实网络验证与模拟故障测试分别记录。检查真实地图是否存在，不能只断言面板出现。
- [ ] 检查隔离：浏览器存储、网络请求、真实行程数据的变更前后对照；不得为了验收写入正式旅行数据。记录调用次数及接口返回状态，不记录密钥。
- [ ] 把所有已观察功能的实现状态、未观察功能、缺失权限和已知差距列给用户，展示可打开的独立预览和对照截图；由用户确认界面效果后进入集成。

## 阶段 8：接入旅游工作台

- [ ] 接入前再次检查 Git 差异与实际运行入口，梳理旧版 `/`、新版 `/next/` 和当前使用的入口。优先研究已有 Vue 工作台地图接入点，而不是盲目替换整个工作台；具体接入位置以代码核实和用户实际入口为准。
- [ ] 定义并实现与工作台的桥接：传入当前旅行城市、地图中心、已有地点和路线；输出选中地点、加入行程、路线方案和聚焦事件。保持统一的坐标系与地点标识，避免将不同接口的数据格式直接混用。
- [ ] 将临时预览状态与工作台持久化状态分开：明确哪些操作只改变地图面板，哪些需要用户主动保存到行程；沿用现有数据模型和备份方式，不自动修改用户的历史旅行。
- [ ] 检查行程面板到地图的定位、地图到行程的添加、日期切换、保存/重开后的路线恢复和去重；界面工具展开时不得遮挡关键操作。保留现有地图服务和原功能，迁移须有清晰的对照与回退步骤。
- [ ] 单独测试旧入口和新版工作台的受影响功能；模拟数据使用隔离测试数据，真实用户数据不参与写入验收。按用户确认的集成效果记录尚存差异。

## 阶段 9：最终验证和交付

- [ ] 运行项目现有构建、单元测试和与地图有关的验证脚本；按受影响范围补充有意义的集成验证。分别列出实际通过、失败、跳过和未执行项，以及真实接口或模拟的区别。
- [ ] 重新截图并由用户查看已集成版本；逐状态比对验收矩阵，不能因为独立预览可用就认定工作台已集成，也不能因为部分路线通过就宣称全站 1:1。
- [ ] 检查最终 `git diff`、`git status` 和新增文件，确认未覆盖或混入用户既有改动。需要提交或合并时，按当时用户授权先审阅再精确操作；推送、部署及付费另行授权。
- [ ] 汇报：实际完成的页面与互动、真实和模拟数据边界、视觉对照、测试结果、未验证/未支持项、Git 状态。若有值得长期保存的项目状态变化，先提出具体记忆更新建议，用户确认后才写入。

## 通过标准

1. 清单覆盖所有已观察到的高德网页入口和状态；未知项及不可用项有证据和明确标记，无假完成。
2. 独立页面和集成页面均显示真实可操作地图，搜索、详情、地图工具和所有已覆盖的路线与面板联动；各自按真实与模拟分别验收。
3. 逐状态视觉对照达到用户认可；动态内容差异、版本差异及未确认界面均保留记录。
4. 工作台原有行程、路线、收藏和备份不因集成受损；已有未提交工作保留，最终 Git 状态可解释。
5. 存在未观察、权限或服务限制而未完成的功能时，明确仍有差距，不能宣布整个高德网页版已经 1:1 复刻完成。
