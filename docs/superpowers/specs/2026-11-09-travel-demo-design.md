# 旅游工作台本地演示设计

用户已在聊天中确认并要求开始制作。以桌面网页为先，手机 App 后续处理。

入口先询问有没有行程。有则填写并保留原文，后续修改不覆盖原文；没有则确定出发地、目的地、天数、日期和预算，再处理具体往返交通。已购票、已选待购和待定分别标记，不强制购票才能继续。日期灵活的用户可比较示例日期价格。

交通、住宿、景点和每日安排可以自由切换。入住日期、人数等已知信息沿用，用户可选择先住宿或先景点。左侧工作区支持表单和直接操作，也提供明确标注的预设聊天演示；右侧地图由用户自主展开/收起，初始不显示。地图展示真实地理底图和示例地点，连线仅表示访问顺序，不作实际导航或时长承诺。

使用杭州三日示例；城市不限于杭州的自由输入要保留，但非示例地点不虚构自动生成结果。所有价格和班次均为演示，不接实时查询、模型或预订。无需复制竞品代码、素材或商标，参考其地图与行程并排的操作思路。保存到本机浏览器，不上线。已填行程可一直查看，不根据示例解析自动篡改。

范围：本地预览目录、任务级设计/计划、验证材料。保留调研、APK、既有 Lvji、密钥和配置。无 Git 仓库，不初始化仓库、不提交，不写长期项目记忆。

验收：首次不显示地图；有行程原文提交后完整保留；可从任意模块继续；地图可开关、切日期后标记和顺序线变化；景点可增删移动且有撤销；费用随人数、天数、酒店变化；示例聊天不能假称真实 AI；刷新可恢复，重置须确认；网络底图失败显示提示与地理示意备用图。
